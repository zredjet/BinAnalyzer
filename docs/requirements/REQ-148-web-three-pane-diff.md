## 背景・動機

TUI版ではツリー・詳細・ヘックスダンプの3ペインレイアウトで対話的な解析が可能である。一方、Web UI（Blazor WebAssembly）は現在ツリー表示とJSON出力のみであり、TUIと比べて機能が限定的。

ブラウザベースのUIは環境構築不要でアクセスしやすいため、TUI同等の機能を提供する意義がある。

### 現在のWeb UIの機能

- ファイルアップロード（ドラッグ&ドロップ / ファイルピッカー）
- フォーマット自動選択（拡張子ベース） / 手動選択
- ツリー表示（折りたたみ可能）
- JSON出力ダウンロード

### 不足している機能

1. **ヘックスダンプペイン** — フィールド選択時に対応バイト範囲をハイライト表示
2. **詳細ペイン** — 選択フィールドのオフセット、サイズ、型、enum値等の詳細情報
3. **Diff機能** — 2つのバイナリファイルの構造差分をブラウザ上で比較

## 機能要件

### 追加する機能

- [ ] ヘックスダンプペイン — 16バイト/行のヘックスダンプ表示。フィールド選択時にバイト範囲をハイライト
- [ ] 詳細ペイン — 選択ノードのメタ情報（オフセット、サイズ、型、enum/flags、バリデーション結果）表示
- [ ] 3ペインレイアウト — ツリー（左）、詳細（右上）、ヘックスダンプ（右下）のレスポンシブ配置
- [ ] Diffモード — 2ファイルアップロードでの構造比較。変更/追加/削除のカラー表示
- [ ] フィールド検索 — ツリー内のフィールド名/値によるインクリメンタルサーチ

### 変更する既存機能

- [ ] `Home.razor` — レイアウトの3ペイン化
- [ ] ファイルアップロード — 2ファイルモードの追加

### 変更しないもの（スコープ外）

- サーバーサイド処理 — 全てクライアントサイドWASMで処理
- バイナリ編集機能 — 表示のみ
- フォーマット定義のオンラインエディタ — 将来課題

## 受入条件

1. [ ] ツリーでノードを選択した際にヘックスダンプペインで対応バイト範囲がハイライトされること
2. [ ] 詳細ペインに選択ノードのオフセット、サイズ、型、値が表示されること
3. [ ] 3ペインレイアウトがレスポンシブに動作すること（モバイル幅では縦積み）
4. [ ] 2ファイルをアップロードしてDiff表示できること
5. [ ] Diff結果で変更/追加/削除が色分け表示されること
6. [ ] フィールド検索でマッチするノードにスクロール・ハイライトされること
7. [ ] 既存テストが全て通過すること（`dotnet test` 全通過）
