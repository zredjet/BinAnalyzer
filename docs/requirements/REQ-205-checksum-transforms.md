## 背景・動機

チェックサムは「範囲のバイト列をアルゴリズムで計算した値 = フィールドの値」の形だけを検証できる。同梱の定義には、この形に当てはまらないために値だけを表示しているものが残っている（各定義の「対応していないもの」・description の「検証しない」）。

| 定義 | チェックサム | 当てはまらない点 |
|---|---|---|
| lz4 | フレームのヘッダのチェックサム | `(xxHash-32 >> 8) & 0xFF`（計算した値の一部） |
| gzip | ヘッダの CRC16（FHCRC） | `CRC-32 & 0xFFFF`（計算した値の下位 16 ビット） |
| otf | ファイル全体の checksumAdjustment | `0xB1B0AFBA - 全体の合計`（定数から引く）。計算では checksumAdjustment を 0 とする |
| otf | head の表のチェックサム | 範囲の中の**別のフィールド**（checksumAdjustment）を 0 として計算する（`exclude_self` は自分の欄しか 0 にしない） |
| tar | ヘッダのチェックサム | バイトの単純な合計で、自分の欄を**空白 8 個**として計算し、値は 8 進数の ASCII の文字列 |
| pe | イメージのチェックサム | 16 ビットの語の和（桁あふれを下に回す）+ ファイルの長さ。自分の欄を除く |

## 機能要件

### 追加する機能

- [ ] **計算した値を式で変換してから比べる指定**（例: `checksum:` の `expected: "{(_computed >> 8) & 0xFF}"`。名前は設計で決める）
- [ ] **範囲の中の別のフィールドを 0 として計算する指定**（例: `zero: [checksumAdjustment]`）
- [ ] **自分の欄を 0 以外のバイトで埋める指定**（例: `self_fill: 0x20`。tar）
- [ ] **文字列のフィールド（8 進数・10 進数の数字）を数値として比べる**（tar）。方法は設計で決める
- [ ] 合計のアルゴリズムを足す: バイトの合計（tar）、16 ビットの語の和で桁あふれを下に回す（PE。インターネットチェックサムの 1 の補数を取る前）。名前は設計で決める

### 変更する既存機能

- [ ] 上の表のチェックサムを同梱定義で検証し、「対応していないもの」から外す

### 変更しないもの（スコープ外）

- 範囲が後ろのフィールドで決まる形（REQ-204）、展開した中身に対するもの（REQ-207）、擬似ヘッダ（REQ-206）
- FLAC のフレームの CRC-8 / CRC-16（フレームを分解していない）

## 受入条件

1. [ ] lz4 の `lz4 -9` の出力のヘッダのチェックサムが ✓、1 バイト書き換えで ✗ になること
2. [ ] FHCRC 付きの gzip のヘッダの CRC16 が ✓ になること（GNU gzip・Python の gzip は FHCRC を書かないので、ヘッダの CRC-32 を Python の zlib.crc32 で求めて作ったファイルで確かめる）
3. [ ] macOS のシステムのフォントの checksumAdjustment と head の表のチェックサムの判定が、fontTools の計算と一致すること
4. [ ] tar（bsdtar・GNU tar の出力）のヘッダのチェックサムが ✓ になること
5. [ ] PE（MSVC・MinGW の出力、またはシステムの DLL）のチェックサムの判定が、`pefile` の `generate_checksum` と一致すること（0 のファイルの扱いを含む）
6. [ ] patch・GUI の編集のチェックサムの再計算が、変換の付いたチェックサムでも正しい値を書くか、書けないことを示すこと
7. [ ] 既存テストが全て通過すること（`dotnet test` 全通過）

## 設計メモ

### 設計方針（案）

- 変換は式で書き、計算した値を特別な変数（`_computed` など）で参照する。比べる相手はフィールドの値（文字列のフィールドなら `parse_int(field, 8)` の結果）
- パッチの再計算は、変換が逆に解ける場合（下位ビットを取るだけなど）だけ対応し、ほかは「再計算できない」と示す

### 懸念事項

- 指定が増えて `checksum:` の組み合わせの検証（排他・必須）が複雑になる
- PE のチェックサムは 0 のファイルが多い（検証されないドライバ以外）。0 を「無し」として扱うか
