## 背景・動機

浮動小数点数の値の表記が、実行環境の言語設定（現在のカルチャ）で変わる。REQ-200 で、手元（ja-JP）で通ったテストが CI（インバリアントカルチャ）で失敗して見つかった。

| 出力 | ja-JP | インバリアント | de-DE |
|---|---|---|---|
| ツリーの 1.5 | `1.5` | `1.5` | `1,5` |
| ツリーの負の無限大 | `-∞` | `-Infinity` | `-∞` |
| **JSON** の負の無限大（文字列で書く。`∞` は `\u221E` にエスケープされる） | `"-∞"` | `"-Infinity"` | `"-∞"` |
| **CSV** の 1.5 | `1.5` | `1.5` | `"1,5"` |

とくに JSON は機械が読む形式なのに、同じファイルでも実行環境で値が変わる（無限大・NaN を `ToString()` で文字列にしている）。上の表は CLI で `LANG`（ja-JP・de-DE）と `DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=1`（インバリアント）を変えて確かめた。CSV も `ToString("G")` で、de-DE では小数点がカンマになり、引用符で囲んだ文字列（数値として読めない）になる。整数は REQ-201 でインバリアントカルチャに揃えた。

現在のカルチャに依る箇所（REQ-203 の作成時点）:

- Output: `JsonOutputFormatter`（浮動小数点数と virtual の double の NaN / 無限大）、`CsvOutputFormatter`、`TreeOutputFormatter`（浮動小数点数・virtual の値）、`HtmlOutputFormatter`、`DiffTreeOutputFormatter`
- Engine: `DiffEngine` の値の文字列
- Presentation / Tui: 詳細・表示文字列の浮動小数点数

## 機能要件

### 変更する既存機能

- [ ] **JSON・CSV の数値の表記をインバリアントカルチャにする**（無限大は `Infinity` / `-Infinity`、NaN は `NaN`。小数点は `.`）
- [ ] ツリー・HTML・差分・GUI / TUI の表示もインバリアントにするか、表示だけは言語設定に従うかを設計で決める（決めた方針を DSL リファレンスか CLI の説明に書く）
- [ ] 同じ入力の出力が言語設定で変わらないことをテストで固定する（カルチャを切り替えて全形式のゴールデンを比べるなど）

### 変更しないもの（スコープ外）

- 日時の表記（virtual の関数が作る文字列）の形式
- UI の文言の多言語化

## 受入条件

1. [ ] ja-JP・de-DE・インバリアントで、JSON と CSV の出力が同じになること（無限大・NaN・小数を含むデータ）
2. [ ] 決めた方針どおりに、ツリー・HTML・差分・GUI / TUI の表示が変わる（または変わらない）こと
3. [ ] ゴールデン（JSON）が変わらないこと（インバリアントで作っている）
4. [ ] 既存テストが全て通過すること（`dotnet test` 全通過。ja-JP とインバリアントの両方）

## 設計メモ

### 設計方針（案）

- 数値を文字列にする処理を、REQ-201 の `IntegerText` と同じく Core の 1 か所（浮動小数点数の表記）にまとめ、各出力から使う
- テストは `CultureInfo.CurrentCulture` を切り替えて出力を比べる。xUnit のテストは並列に動くが、カルチャはスレッド（非同期の流れ）ごとなので互いに影響しない

### 懸念事項

- ツリーの表示を変えると、ja-JP の利用者には無限大が `∞` から `Infinity` に変わる
