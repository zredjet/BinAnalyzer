## 背景・動機

REQ-177 はデスクトップ（Photino.Blazor、.NET ランタイム上）で計測・改善した。GUI コンポーネントは Web（Blazor WebAssembly）と共有だが、WASM ではランタイムがインタプリタ実行（AOT 無し）で単一スレッドのため、同じファイルでもデコードと索引構築は数倍〜十数倍遅くなり、100 MB の上限（`FilePicker.MaxSizeMb`）でも UI が長時間固まる可能性がある。Web 版の実測が無い。

## 機能要件

### 追加する機能

- [ ] Web 版で 10 MB / 50 MB / 100 MB のファイルを開く時間（デコード / 索引 / 最初の描画）と、選択・スクロールの反映時間を計測し `docs/benchmark-baseline.md` に記録（`BINANALYZER_GUI_TIMING` 相当のログをブラウザコンソールに出す）
- [ ] 計測結果に基づく対応。候補:
  - `RunAOTCompilation` の有効化（サイズ増とビルド時間のトレードオフを記録）
  - デコード中の進捗表示と UI の応答維持（`await Task.Yield()` を挟むデコード、または Web Worker）
  - 100 MB 上限の見直し（実測に基づく値へ）

### 変更しないもの（スコープ外）

- デスクトップ版の変更（REQ-177 で対応済み）
- エンジンのメモリ削減（REQ-180）

## 受入条件

1. [ ] 計測結果が `docs/benchmark-baseline.md` に記録されていること
2. [ ] 50 MB のファイルを開いている間もブラウザが「応答なし」にならないこと（進捗表示がある、または 1 秒以内に UI が反応する）
3. [ ] 既存テストが全て通過すること（`dotnet test` 全通過）
