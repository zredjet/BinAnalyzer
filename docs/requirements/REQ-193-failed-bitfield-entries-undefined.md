# REQ-193: エラー継続モードで読めなかった bitfield のエントリの名前を未定義にする

## メタ情報

| 項目 | 値 |
|---|---|
| ステータス | done |
| 優先度 | 高 |
| 依存 | なし（REQ-188 のデータ・その他の見直しのファズで見つかった） |
| 作成日 | 2026-09-25 |
| 更新日 | 2026-09-25 |

## 背景・動機

エラー継続モード（`--on-error continue`）で読めなかったフィールドは、その名前を「未定義」にしている（`MarkVariableUndefined`）。後ろの式が外側のスコープや前の要素の同名の値を拾わないようにするためである。ところが bitfield は、フィールドの名前だけを未定義にして、**エントリの名前**（`major_type` など、式から実際に引かれる名前）はそのまま残していた。

REQ-188 で書き直した CBOR の定義で、途中で切れたデータを読むと、読めなかった値の `major_type` / `additional_info` に**親の値**が見えた。親がマップ（2 エントリ）なら子もマップとして読み、子の子も……と入れ子の深さの上限（64）まで 2 倍ずつ増え、ファズのテスト（途中で切ったデータ）がメモリ不足で止まった。再帰する定義（CBOR・Parquet の Thrift・X.509 の DER など）はどれも同じ形で壊れうる。

## 機能要件

### 変更する既存機能

- [x] **エラー継続モードで読めなかった bitfield は、フィールドの名前とすべてのエントリの名前を未定義にする。** 後ろの式でその名前を引くとエラーになり（外側の値を使わない）、再帰しない

### 変更しないもの（スコープ外）

- 停止モード（最初のエラーで止まる）
- struct の途中で失敗したときの、struct の中の他のフィールド（それぞれのフィールドが自分で失敗・成功する）

## 受入条件

1. [x] 前に同じ名前のエントリを持つ bitfield を読んでいても、読めなかった bitfield のエントリを引く virtual がエラーになること（Engine のテスト）
2. [x] 途中で切った CBOR（RFC 8949 の例の 145 バイト目まで）が 1 秒かからずに読み終わること（旧: メモリ不足）
3. [x] ファズのテスト（ランダム・変異・途中で切る）が全て通ること
4. [x] 既存テストが全て通過すること

## 影響範囲

|---|---|
| BinAnalyzer.Engine | `BinaryDecoder.MarkFieldUndefined`（フィールドの名前と bitfield のエントリの名前）を、エラー継続モードの 2 つの catch で使う |

## 設計メモ

- エントリの名前も bitfield の値の一部として束縛される（読めたときは `PromoteDecodedValues` と同じくエントリごとに変数になる）ので、読めなかったときも同じ名前を未定義にするのが対称
- 定義の側で「読む前に既定値の virtual を置く」ことでも避けられるが、再帰する定義のすべてに必要で、書き忘れるとファズでしか見つからない。エンジンで直す
